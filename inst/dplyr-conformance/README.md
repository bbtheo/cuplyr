# dplyr conformance harness (Phase 13)

This directory is **vendored, third-party source**, not cuplyr source code.
It holds a copy of dplyr's own `tests/testthat/` suite, used by
`tools/run-dplyr-conformance.R` to measure how much of dplyr's *actual* test
suite passes when run against `tbl_gpu` instead of a tibble/data.frame.

It is never imported, exported, or exercised by cuplyr's own R code, and
`pixi run test`/`R CMD check` never runs anything under here -- it is purely
an opt-in developer tool, driven from `tools/`. Note the one packaging
nuance: because it lives under `inst/` (the path this task specified), a
plain `R CMD INSTALL .` DOES copy it into the installed package directory
verbatim, same as any other `inst/` content (`.Rbuildignore` only affects
`R CMD build`'s source tarball, not a direct source-directory install --
verified empirically, not assumed) -- so it is excluded from
`.Rbuildignore` deliberately for `R CMD build`/release-tarball purposes,
but a locally `pixi run install`-ed copy of cuplyr will still have this
~1.1 MB of vendored test fixtures sitting alongside the real package files.
Harmless (never loaded/executed by anything except explicitly running
`tools/run-dplyr-conformance.R`), but worth knowing if repo size or a
minimal install footprint ever becomes a concern.

## Provenance

- Vendored by `tools/sync-dplyr-conformance.R` (committed, re-runnable script
  -- never hand-copied).
- Source: a locally installed copy of dplyr that still ships its
  `tests/testthat/` directory (CRAN binaries normally strip `tests/`; see
  `PROVENANCE.txt`, regenerated on every sync, for the exact path/version/date
  used for the last sync).
- dplyr version actually vendored: **1.2.0** (the only local install with a
  `tests/` directory available at sync time was under the R 4.5 library; the
  R 4.6 library's dplyr 1.2.1 install -- the version cuplyr's `DESCRIPTION`
  nominally targets -- ships no `tests/` directory at all, a normal CRAN
  binary trait). 1.2.0 -> 1.2.1 is a patch release; the sync script's fallback
  path (shallow clone of `tidyverse/dplyr@v1.2.1`) is documented and used
  automatically the next time this is re-synced somewhere without a
  tests-shipping local install.
- Re-sync any time with `Rscript tools/sync-dplyr-conformance.R` from the repo
  root.

## Layout

```
inst/dplyr-conformance/
  README.md         # this file
  PROVENANCE.txt     # regenerated by the sync script every run
  manifest.R         # per-file runnable/out-of-scope classification + reasons
  tests/
    test-*.R         # vendored dplyr test files, verbatim
    helper-*.R       # vendored dplyr test helpers, verbatim
    _snaps/          # vendored expect_snapshot() reference output
    utf-8.txt         # fixture data file used by helper-encoding.R
```

## Running the harness

```r
Rscript tools/run-dplyr-conformance.R
```

See `tools/run-dplyr-conformance.R`'s own header comment for the shim
mechanism, its limitations, and output format. The generated ledger lives at
`scratchpad/dplyr_conformance_report.md` (a scratchpad artifact, not
committed documentation -- regenerate, don't hand-edit).
